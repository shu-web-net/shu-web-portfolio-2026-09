# microCMS スキーマ セットアップ手順

`docs/microcms-schema.md` の設計をベースに、現行WPサイト調査（`memory` / 下記「決定事項」参照）を反映して確定したスキーマ。
`schema/*.json` を各APIの作成時にインポートすれば、手作業のフィールド追加を省ける。

## 決定事項（2026-09-07）

現行サイト調査の結果、当初設計から以下を変更した。

- **categories は作らない**：現行カテゴリ（Web制作/健康/プログラミング）は全記事がWeb制作に属し実質機能していないため廃止。代わりに blogs に `type`（記事/日報）と `featured`（注目）を持たせる。
- **`type`（記事/日報）**：220件中69件が日報・週報系。移行時にタイトル接頭辞（日報/週報/月報）で自動判定して初期値を入れる。トップは記事を主役に、日報はアーカイブ送りにできる。
- **`featured`（注目記事）**：見せたい技術記事を数本ピックしてトップに大きく出すための真偽値。手動でON。
- **日報3件の日本語スラッグ**（`日報2025-08-31` 等）は英字（例 `nippo-2025-08-31`）に振り直す。
- **works 12件は自動移行しない**：現行works投稿タイプにはクライアント名露出（例「Ninchy様サイト」）があり、ACF詳細もREST非公開。後工程で手動リライト（業種＋規模表記）する。

## ファイル

| ファイル | API名 | 形式 | 備考 |
|---|---|---|---|
| `schema/blogs.json` | `blogs` | リスト形式 | 記事本体。`type`/`featured` 込み |
| `schema/works.json` | `works` | リスト形式 | `techStack` はセレクト（複数選択）。選択肢は初期セット入り、後から追加可 |
| `schema/profile.json` | `profile` | **オブジェクト形式** | API作成時に「オブジェクト形式」を選ぶこと |

## blogs のフィールド

| fieldId | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `title` | タイトル | テキスト | ✓ |
| `content` | 本文 | リッチエディタ(v2) | ✓ |
| `eyecatch` | アイキャッチ | 画像 | |
| `originalPublishedAt` | 元の公開日 | 日時 | ✓ |
| `description` | メタ説明 | テキストエリア | |
| `type` | 種別 | セレクト（記事/日報・単一選択） | |
| `featured` | 注目記事 | 真偽値 | |

- **contentId = WPスラッグ**。URL `/blog/{slug}/` を維持しSEO流入を守る（日報3件のみ英字振り直し）。
- 表示・並び替えは `publishedAt` ではなく `originalPublishedAt` を使う。

## 作成手順（各API共通）

1. **microCMSサービスを新規作成**（ポートフォリオ用。既存サービスとは分ける）
2. 「コンテンツ（API）を作成」→ エンドポイント名（`blogs` / `works` / `profile`）とAPI名を入力
3. API形式を選択（blogs・works=**リスト形式**、profile=**オブジェクト形式**）
4. スキーマ定義のステップで「**スキーマをインポート**」を選び、対応する `schema/*.json` を読み込む
5. 内容を確認して作成

作成順はどれからでもよい（相互参照フィールドは無い）。

## contentId に元スラッグを使う設定

- **移行スクリプト（Management API）でPOSTする場合**：リクエストボディに `id` を含めれば指定した値がcontentIdになる。特別な設定は不要。
- 管理画面から手動作成する場合に備え、blogsのAPI設定で「任意のIDでコンテンツを作成する」相当を有効化しておくとよい。

## APIキーの発行（スキーマ作成後）

`docs/microcms-schema.md` の権限設計に従い2種類発行する。

- **読み取り用（GET のみ）**：Next.jsビルド時のコンテンツ取得用。GitHub Secrets に登録。コミット禁止。
- **書き込み用（GET/POST/PUT/PATCH/DELETE）**：記事移行スクリプト専用。移行完了後に無効化または削除。ローカル `.env` にのみ置く。

## 設計上の注意（再掲）

- 画像は移行しない。本文中の `/wp-content/uploads/...` はXserverに残すのでURLそのままで生きる。
- 本文に Pochipp（アフィリンク管理プラグイン）のブロック残骸が混ざる可能性あり。移行ドライランで確認する。
- `works.title` はクライアント名を出さず「業種＋規模」で表記する。
