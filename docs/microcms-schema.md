# microCMS スキーマ設計書

ポートフォリオ用に新規microCMSサービスを作成し、以下のAPIを作る。

## API一覧

| API名（エンドポイント） | 種類 | 用途 |
|---|---|---|
| `blogs` | リスト形式 | ブログ記事（WordPressから約220件を移行） |
| `categories` | リスト形式 | 記事カテゴリ |
| `works` | リスト形式 | 制作実績 |
| `profile` | オブジェクト形式 | 自己紹介・スキル（1件のみ） |

## APIキーの運用ルール

書き込み用APIキー（Management API）は普段OFFにしておく。記事・実績・プロフィールをPATCH/PUTで更新する作業の直前だけ本人がmicroCMS管理画面でONにし、作業完了後は毎回OFFに戻す。

## blogs（ブログ記事）— リスト形式

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| （contentId） | — | — | — | **WordPressのスラッグを使う**。URL `/blog/{slug}/` を維持しSEO流入を守る |
| `title` | タイトル | テキストフィールド | ✓ | |
| `content` | 本文 | リッチエディタ | ✓ | WordPressの本文HTMLをそのまま流し込む |
| `eyecatch` | アイキャッチ | 画像 | | 無い記事もある想定 |
| `category` | カテゴリ | コンテンツ参照（categories） | | |
| `originalPublishedAt` | 元の公開日 | 日時 | ✓ | WP側の公開日。表示・並び替えはこちらを使う（登録日ではなく） |
| `description` | メタ説明 | テキストエリア | | meta description用。無ければ本文冒頭から生成 |

> 注：microCMSの標準フィールド `publishedAt` は「microCMSでの公開日時」になり、移行時は登録日に近い値になる。元の公開順を守るため `originalPublishedAt` を別に持つ。

## APIキーの権限設計

- **読み取り用（GET）**：Next.jsのビルド時にコンテンツ取得。GitHub Secretsに登録
- **書き込み用（POST/PUT）**：記事移行スクリプト専用。移行完了後は無効化または削除してよい
- キーは絶対にコミットしない。ローカルは `.env`、CIはGitHub Secrets

## 記事移行の方針（WordPress → microCMS）

移行スクリプト（Node.js 100行前後）でまとめて流し込む。

### フロー
1. WP REST API `https://shu-web.jp/wp-json/wp/v2/posts?per_page=100&page=N` で全記事取得（ページネーション対応、3リクエスト程度）
2. カテゴリを先に `categories` へPOST
3. 各記事を変換して `blogs` へPOST（contentId=WPスラッグ、originalPublishedAt=WP公開日）
4. microCMS書き込みのレート制限対策で1件ごとに0.5秒程度ウェイト（220件で約2分）

### 実装上の注意
- **レジューム対応**：登録済みIDをログに書き出し、再実行時はスキップ（文字化け・巨大記事でのエラー停止に備える）
- **本文HTML**：microCMSリッチエディタはHTML文字列を受け取れる。大きな加工は不要
- **画像は移行しない**：本文中の `/wp-content/uploads/...` のURLはそのまま。Xserverに残すので生き続ける
- **下書き・非公開記事**：REST APIのデフォルトは公開記事のみ。下書きも移すなら要認証取得

### 実行手順
1. まず5件でドライラン（リッチエディタでの見え方・画像表示・日付を確認）
2. 全220件を本番実行
3. 検証：件数の突き合わせ＋ランダム数件のタイトル・本文長を比較（欠落チェック）
